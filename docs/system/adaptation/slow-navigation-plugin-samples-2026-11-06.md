# 2026-11-06 慢资源切页与插件隔离样本补验

本批仅处理主题对现有插件的接入生命周期，保持原有样式、图标与文案。没有修改插件、配置、数据库或站点业务数据，没有 Git 暂存、提交、推送或发布。

## 确认问题及修复

**旧页面的资源回调可能干扰新导航。** 原先 `pageGeneration` 在 DOM 替换前才递增；新访问已经开始但响应仍在等待时，旧页面的 5 秒模块超时仍属于同一代，可能执行 `location.reload()`。真实浏览器修复前以 `/photos → /links` 复现：旧模块延迟 7.5 秒、下一页响应延迟 8.5 秒，旧文档在约 5 秒时被刷新。此场景没有跨出 Shiki 配置路径，不属于插件要求的整页导航。

修复位置：`src/common/main.js`，构建输出 `templates/assets/js/main.js`。

- 按 Swup 的 visit、DOM 代际及 URL 共同判断结果归属；新访问等待期间，旧超时、error、ready 和已排队 rAF 不得刷新或挂载旧页。
- 真正替换 DOM 后取消旧计时器与事件监听；取消新访问并恢复原 URL 时，保留页面可以恢复一次初始化。`Visit.abort()` 本身不恢复历史，本批未添加历史重写。
- 官方插件脚本尚未就绪时，兼容事件暂存；离页则丢弃，保留原 DOM 并恢复 URL 时再派发一次。
- 独立审查发现修复中的 URL 判断会阻止 Links 规范化查询及本地筛选后的兼容事件；已补齐同页状态规则及取消恢复后的 owner 恢复。派发 detail 使用当前 URL。
- 当前页面自己的模块失败/超时仍可整页恢复；Shiki 无销毁 API 的配置路径边界仍按既有契约整页导航。

采用 [Swup 官方 hooks](https://swup.js.org/hooks/) 的 `visit:start/end/abort`、`content:replace` 生命周期；并核对实装 Swup 4.10.0 的 `navigate.ts`、`Visit.ts`。没有虚构插件 API 或用禁用插件掩盖问题。

## 人工检查

1. `/photos?preview-theme=theme-sky-blog-1`：浏览器禁缓存、限制网络速度，图库尚在等待时进入 `/links?preview-theme=theme-sky-blog-1`。停留等资源结束，应该保持目标友链页，不能突然刷新回图库或挂载错页。
2. 连点图库、友链、图库；加载过程中后退。核对最终地址、标题与实际内容相符；当前页面网络真正失败时，整页恢复仍是保留的兜底。
3. `/links?view=links&preview-theme=theme-sky-blog-1`：允许主题规范化查询；进入动态/分组再离开返回，控件应正常。没有给原有图标增加文字。
4. `/archives/editor-feature-demo?preview-theme=theme-sky-blog-1`：查看真实组件；本轮折叠压力样本只存在于验收浏览器，刷新后消失，不会显示在你的正文中。
5. 文档全局设置页：真实版本选择器应保持正文路径；本轮额外语言项也是临时样本，刷新后消失。手机先滚动显示并展开文档工具，再开文档菜单。
