# Shiki 迟到启动修复与剩余插件隔离验证（2026-11-06）

本批只修复主题对官方插件的生命周期接入。保留原有视觉、图标与文案；没有修改插件文件、站点配置或业务数据，没有暂存、提交、推送或发布。

## 已确认的原因与修改

主题此前用动态内联模块的 `load` 事件判断 Shiki bootstrap 完成，但内联脚本本身不会产生这一成功事件。它在 6 秒后被永久记为不确定，真实完成也不能纠正状态。同配置下次切页因此误触发 `plugin-bootstrap-changed` 整页恢复；若监听器注册晚于兜底事件，当前正文还会错过高亮。

[HTML Standard 的执行步骤](https://html.spec.whatwg.org/multipage/scripting.html#execute-the-script-element)规定成功 `load` 仅由外部脚本元素派发。本批浏览器替身在官方启动代码前加入可控执行等待，保留原 import 和初始化内容：修复前 7 秒后已确认模块正文执行，但代码块未高亮；下次同配置访问的追踪记录明确显示错误重载。它证明一个真实主题触发条件，**不能反推上一批未捕获原因的那一次重载必定由此导致**。

| 位置 | 本批修改 | 方法与边界 |
| --- | --- | --- |
| `src/common/js/plugin-script-lifecycle.js` | 给主题重放的 Shiki 内联模块末尾添加一次性完成信号；把“等待超时”和“最终执行结果”分开 | 原插件制品未改；保留原始 bootstrap 内容用于配置比较。超时后继续接收真实成功/错误，清理监听，拒绝旧 token 干扰 |
| `src/common/main.js` | 保存当前页面的插件动作；迟到成功后，仅向有效页面补发 `pjax:complete` | 按 Swup visit、DOM 代际及 URL 校验；下一页等待时暂存，DOM 替换后丢弃旧动作；已有全量兼容事件待执行时不重复补发 |
| 两个既有验证脚本 | 更新真实内联模块完成夹具，增加迟到成功/失败、token 隔离及切页归属用例 | 不再人工派发 `load` 假装内联模块成功；移除完成信号、误发全部事件、绕过归属判断的内存反验均能令用例失败 |
| `templates/assets/js/main.js` | 由当前源码重新构建 | 其他既有 WIP 保留，未以 Git 累计 diff 冒充本批修改 |

沿用 [Swup 官方生命周期](https://swup.js.org/hooks/)和实装 Shiki 已有 `pjax:complete` 监听。该事件是公共广播；本批仅确认当前读取的页面脚本消费组合，不能承诺未来任意插件都没有额外响应。[Shiki 官方说明](https://github.com/halo-sigs/plugin-shiki/blob/a13a43f100d04f8739fc0b230cd3f8ef597bb0e1/README.md)仍提示额外路径与 PJAX 的兼容边界，所以配置改变、离开配置范围或结果仍不确定时继续整页导航，未强行改成所有页面 PJAX。

本批未改首屏登记方式：当前官方 1.5.1 输出是位于主题入口之前的普通 parser-inserted module，无 `async` 或顶层 `await`。原始首屏进入文档后再同配置切页，双端保持同一 document；人工插入顶层等待的隔离场景不能直接推导当前官方首屏存在同一缺陷。

## 人工复核入口

1. `/docs/halo-theme-sky-blog-1/theme-settings/global?preview-theme=theme-sky-blog-1`：从首页通过站内链接进入，等待资源完成后再切同配置文档。应保持正常正文和高亮，不因已完成的脚本再次整页刷新。额外压力代码块只在验收浏览器临时响应中存在。
2. `/archives/editor-feature-demo?preview-theme=theme-sky-blog-1` 与 `/archives/CNnnwQh7?preview-theme=theme-sky-blog-1`：用于 AI/受限组件隔离样本及来回切页。样本不会出现在保存的正文中；刷新后恢复实际内容，不能把普通路由没有样本误认为适配失效。
3. 开发者工具禁用缓存后核对请求使用 `/themes/theme-sky-blog-1/assets/`；后台活动主题为另一个主题时必须保留预览参数。整页导航进入或离开 Shiki 配置范围仍是有意保留的兼容措施。
